# A release checklist that outgrew the window

| ID | Challenge | Context | Next step | Status |
| --- | --- | --- | --- | --- |
| DX-01 | Read long descriptions without horizontal scrolling or losing the relationship between a task and its evidence. | A release checklist has grown into several hundred characters per row. Every cell contains useful context, but wrapping the entire Markdown line mixes unrelated columns together. | Fit each column to the window, keep identifiers compact, and expand only the record that needs a closer look. | Ready for review |
| DX-02 | Compare two detailed alternatives while keeping the record identifier visible throughout the discussion. | The architecture note contains the proposed design, rejected alternatives, migration risks, and validation evidence in separate columns. Reading all of them at once obscures the comparison. | Select the interesting column and press f to focus on it alongside the first column. Restore the complete table with a. | In progress |
| DX-03 | Keep short status values useful without letting an occasional long explanation consume the entire table width. | Most rows contain a one-word status, but a few include an explanation of which dependency is missing and who should investigate it. A fixed width is either wasteful or too narrow. | Use c for a one-line column preview. The complete text remains available in the full-width row reader and the source buffer. | Waiting for the compatibility checks to finish |
| DX-04 | Inspect a long migration procedure as ordinary paragraphs instead of a tall, narrow strip of wrapped words. | The procedure includes preparation, a reversible trial, verification of the new state, and the conditions under which the operator should stop and roll back. None of those details should be lost. | Press v for a labeled record view, move between fields with Tab, and use Ctrl-d to scroll through long content. | Ready for review |
| DX-05 | Hide columns that are useful during planning but irrelevant while reviewing the actual implementation. | Ownership notes and scheduling details matter to the project coordinator. A reviewer currently needs the problem statement and acceptance evidence, with enough width to read both comfortably. | Hide the selected column with x, restore an individual field with u, and reset the whole layout with R when changing tasks. | Ready |
| DX-06 | Preserve the connection between a rendered preview and the exact Markdown cell that needs editing. | Copying a shortened preview into an editor can accidentally omit qualifications. Reformatting the source simply to read it also creates noisy diffs and changes unrelated whitespace. | Yank the complete original cell with y or press g to return to its exact source position. Reading never changes the document. | Verified |
| DX-07 | Follow one record across a large table without repeatedly searching for the corresponding column headings. | A checklist contains enough rows to fill several screens. Once the original header scrolls out of view, similar prose in neighboring columns becomes difficult to identify confidently. | Keep column labels in a fixed header and highlight both the active record and the selected cell while navigating with j and k. | Verified |
| DX-08 | Read the same document in a narrow split while another file remains open for comparison. | Developers often review a design note next to the code it describes. Giving the table the entire terminal would remove useful context, while keeping every column narrow would hurt readability. | Recalculate widths when the split changes. When useful columns no longer fit, show the selected record as full-width fields automatically. | Verified |
| DX-09 | Search the complete table only after making sure the relevant text is actually visible in the reader. | Compact previews deliberately omit text after a few lines. A search limited to those previews could miss the sentence that contains an important acceptance condition or a reference identifier. | Press a and w to restore columns and expand all rows before using native slash search. The source buffer always contains the original text. | Documented |
| DX-10 | Display Unicode and long identifiers without breaking column boundaries or splitting composing characters. | International names, wide characters such as 東京, and tokens like `feature/keep-table-columns-readable-during-review` have different display widths from their byte lengths. | Measure screen cells, wrap at word boundaries where possible, and split an overlong token only when it cannot fit on a line. | Covered by checks |
| DX-11 | Distinguish literal pipe characters from separators when a cell contains a code example or a regular expression. | A command such as `left\|right` should remain inside one cell. A parser that splits on every pipe would shift later values into the wrong columns and make source navigation misleading. | Respect escaped pipes, retain inline Markdown, and recognize optional outer pipes and alignment markers without depending on Treesitter. | Covered by checks |
| DX-12 | Keep the reader usable when another plugin already prettifies Markdown in the source buffer. | Concealment, virtual text, and table borders can improve the document view but cannot provide every reading interaction. Applying two renderers to the same display would produce overlapping decorations. | Open the reader in a separate mdtable scratch buffer and let the existing Markdown renderer continue handling the original document. | Compatible |
| DX-13 | Let light and dark colorschemes control table contrast without changing unrelated editor highlights. | A theme may want muted separators, stronger labels, a soft row background, and a distinct selected cell. Reusing generic search colors everywhere gives the theme too little control. | Expose named MdTable highlight groups with native default links. Colorscheme definitions take precedence and survive repeated setup calls. | Ready |
| DX-14 | Move through records quickly while retaining the ability to copy a complete field into a chosen register. | During review, a developer may need the fourth record, then its evidence field, then a copy for a commit message. Ordinary visual selection across wrapped table text is awkward. | Navigate with counts such as 3j, switch columns with h and l, and use a named register before y to copy the complete original cell. | Verified |
| DX-15 | Recognize when the document changed after the reading snapshot was opened. | Another window can edit the same buffer while the reader remains open. A previously correct line and byte position may then refer to different content, even if the preview still looks familiar. | Refuse a stale source jump and reopen the reader to refresh its snapshot. Never write the old preview back into the document. | Verified |
| DX-16 | Install the plugin without adopting a second package manager or running a configuration generator. | Some configurations use Lazy while others rely on Neovim packages. Both should get the same command, key behavior, and default styling from the same small Lua implementation. | Use the standard lua, plugin, and doc directories. Provide Lazy and native package examples, with no mandatory setup call. | Ready |
| DX-17 | Verify the release from an isolated checkout instead of relying on modules inside a developer's config directory. | A local module can accidentally import a sibling file or assume a particular working directory. Those assumptions become visible only after someone installs the repository on a clean machine. | Run parser and window checks from the standalone repository and exercise native loading on the minimum supported Neovim version. | In progress |
| DX-18 | Show the interaction in a short terminal recording that can be replayed or viewed directly on GitHub. | A static screenshot cannot demonstrate how widths redistribute after hiding a column, how a record expands, or how the reader returns to the original source without modifying it. | Record actual Neovim output as an asciicast and render it to a looping GIF, using this synthetic checklist as the public fixture. | Ready to record |

## Quick acceptance checks

| Claim | Witness |
| --- | --- |
| The table stays readable | Every rendered line fits the available window width |
| Full text stays accessible | Expanded rows, full-width fields, and complete-cell yanks |
| Source editing stays ordinary | Jump back to the original cell without changing its text |
| Theme control stays local | Dedicated highlights for labels, borders, rows, and cells |
| Installation stays portable | The same command works with Lazy and native packages |
